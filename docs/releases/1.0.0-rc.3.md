# My Collection 1.0.0-rc.3

Release candidate prepared on 2026-11-03. This is a prerelease update package for an existing installation.

## Included changes

- An improved admin panel with searchable navigation, mobile navigation, keyboard support and collection shortcuts.
- Redesigned biography pages with complete portraits, readable articles, profile facts and linked public collection records. The directory includes search, alphabet filters and pagination.
- Wishlist tracking for wanted stamps and covers, with multiple seller links, price history, currency and shipping comparisons, target prices and collecting statuses.
- Collection completeness checklists by country, year, series or theme, highlighting missing items.
- Private storage locations, purchase details, valuations and notes alongside public collection information.
- Bulk editing with a preview of each change before confirmation.
- Printable A4/Letter album PDFs with selected records, captions and optional QR links.
- Preserved high-resolution originals with proportional previews, full-image viewing and public-record download checks.
- The existing Custom / Theme Studio archive, item and search improvements from RC2.

## Deployment

1. Back up the existing database, configuration and uploads, and test this candidate on a staging copy first.
2. Use PHP 8.2 or newer with Composer's required extensions and the application's GD, fileinfo and PDO MySQL extensions. Production dependencies are bundled from `composer.lock`; no Composer installation is needed when deploying this ZIP. Source-only installations must run `composer install --no-dev`.
3. Extract the update while retaining the installation's `config/config.php`, private environment configuration and uploads. These files are intentionally absent from this archive. Keep `uploads/`, `includes/cache/` and `tmp/` writable.
4. Apply the feature SQL once from the `BEGIN approved collection tools and seller price tracking (2026-11-02)` block in root `update.sql`. Alternatively, apply `scripts/wishlist_offers_update.sql` and `scripts/collection_workbench_update.sql`; these contain the same SQL, so do not apply both copies. The SQL uses the project's existing MariaDB syntax, including `ADD COLUMN IF NOT EXISTS`, matching the supplied MariaDB 10.4 schema. Earlier migrations remain cumulative in `update.sql`.
5. In Admin → Modules, enable **Collection Workbench**, **Wishlist**, and **People & Biographies** as needed. Existing module choices and settings are preserved. Select Custom in Theme Studio for the archive design.
6. Follow `docs/operations/collection-tools.md` for the collecting workflows and deployment details.

## Verification and remaining checks

Application syntax, the wishlist, collection workbench, biography, album PDF and media/export regression suites passed with isolated fixtures. Biography pages were checked at desktop and phone sizes. The package is checked for dependency/platform compatibility, required runtime files, ZIP integrity and SHA-256 hashes for every included file.

Live MariaDB migrations and real S3 transfers still require verification in the deployment environment. The new code displays migration notices when required tables or columns are absent. Existing free-text seller prices remain visible until numeric prices and currencies are supplied. High-resolution originals that no longer exist cannot be reconstructed from older cropped images.

The lock file retains pre-existing Composer advisories affecting `guzzlehttp/guzzle`, `guzzlehttp/psr7`, and `mtdowling/jmespath.php`, including a critical JMESPath compiler issue. Resolve those advisory-guided dependency updates before a production rollout. This candidate retains the reviewed feature scope; the new PDF/QR packages had no advisories in the preceding scan.

## Package contents and integrity

The ZIP includes application code, compiled CSS, migration SQL, operational scripts and a clean production `vendor/` directory. It excludes private configuration, user uploads, runtime caches, agent/Git metadata, `node_modules`, development/test tools, preview artifacts and generated design references.

`RELEASE-MANIFEST.json` records each included file's size and SHA-256 checksum, excluding itself. A matching manifest, release notes and ZIP checksum are also supplied as separate release assets. GitHub's automatic source archives are source snapshots; use the named `mycollection-1.0.0-rc.3-2026-11-03.zip` asset for this deployment package.
